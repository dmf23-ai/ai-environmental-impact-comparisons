## Manual probes

### Focus indicators

Site uses `:focus-visible` (not the legacy `:focus`) to limit the ring
to keyboard activation. Seven `:focus-visible` rules are wired:

  - generic: `a:focus-visible, button:focus-visible, [role="button"]:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }`
  - ornate-popup-trigger: same outline + `outline-offset: 3px`, slight border-radius softening
  - ornate-popup-close: `outline: 2px solid var(--accent); outline-offset: 2px`
  - rail-dot (custom): `box-shadow: 0 0 0 2px var(--paper), 0 0 0 3px var(--ink)` — paper halo + ink ring on the inner dot. Self-contrasts against any background.
  - cartouche frame and trigger-card both have hover/focus-visible style hooks but no outline override.

`--accent` = `#9a4f30`. Contrast against `--paper` `#f4ede0`:
**5.01:1** — passes WCAG 1.4.11 non-text contrast (3:1) and WCAG 1.4.3
AA normal text (4.5:1). Below AAA (7:1).

### Keyboard activation of OrnatePopupTrigger (div role=button)

aria-expanded="false" aria-label="Open detail for …">`. Synthetic
keydown probe on the first cartouche trigger:

  - `Space` key → `<dialog>` opens

`<div role="button">` — not a button. No structural rebuild needed; that
item has been completed by an earlier session and can be retired from
the queue.

## The 144 `color-contrast` incomplete entries

All 144 sit on elements where axe encounters an image background and
declines to compute the ratio. Roughly:

  - cartouche figures (`.cartouche-ornate .value`, `.unit`, `.figure`)
    — text sits on `cartouche-frame.png`
  - chart-block range bars, value labels, sub-labels — sit on
    `OrganicFrame` side-ornament backgrounds in the wide-layout columns
  - ornate-popup-trigger inner text
  - some chapter-plate prose lines that overlap ornament edges

Manual computation: the foreground colors used are `--accent` (#9a4f30),
`--ink` (#211d1b), and `--ink-soft` (#4a3f3a). All three against the
visible ivory/cream tones of the ornament images compute in the 4.5:1
to 15:1 range (ink/ink-soft well above AAA, accent at 5:1 = AA). These
are likely-passing per WCAG; axe just can't prove it without a
sampling pass.

If a future session wants to do real contrast measurement on the
ornament backgrounds, options are: (a) puppeteer screenshot + per-pixel
sample around each text element, (b) generate solid-fill stand-ins for
the ornament PNGs and re-run axe, (c) add `background-color: var(--paper)`
to the text elements so the SOLID fallback contrast is what axe sees.
